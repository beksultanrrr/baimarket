# Замечания по документу «Live-стримы (LiveKit) — контракт для мобильного приложения»

1. **Срок действия токена LiveKit.** Не определён TTL viewer- и publisher-токенов, а также поведение клиента при истечении токена во время длительного эфира. Требуется указать срок действия и регламент обновления (повторный вызов `POST /live/:id/token` при разрыве соединения).

2. **Отсутствует событие удаления сообщения.** Эндпоинт `DELETE /live/chat/:messageId` предусмотрен, однако в перечне событий «сервер → клиент» нет уведомления об удалении. В текущем виде удалённое сообщение не скрывается у зрителей в реальном времени. Необходимо либо добавить событие `chat:deleted`, либо явно зафиксировать, что удаление применяется только к истории.

3. **Формат события `error`.** Событие содержит только `message`. Для локализации на стороне клиента (приложение поддерживает три языка) требуется добавить поле `code` (например, `rate_limit`, `forbidden`, `validation`, `not_live`).

4. **Эндпоинт `GET /live`.** Не определены порядок сортировки и наличие пагинации. Требуется уточнить при возможном росте количества одновременных эфиров.

5. **Поведение `joinStream` для неактивного стрима.** Не описана реакция сервера при `joinStream` по стриму со статусом, отличным от `LIVE` (ошибка, пустой `snapshot` или отсутствие ответа). Требуется зафиксировать.

6. **Лайки и подарки.** В макетах экрана эфира присутствуют соответствующие элементы, в контракте они отсутствуют. Требуется явно указать, что данный функционал в контракт не входит.

7. **Управление socket-соединением.** Формулировка «один socket на стрим» требует уточнения: переиспользуется ли соединение через `leaveStream`/`joinStream` при переходе между эфирами или устанавливается новое.

8. **Задержка счётчика зрителей.** Указано, что `viewers` формируется из вебхуков LiveKit. Рекомендуется отметить ожидаемую задержку доставки, чтобы корректно интерпретировать поведение счётчика в UI.
